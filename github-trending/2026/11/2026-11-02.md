## 逐项深度分析

### 🥇 No.1 — vercel-labs/agent-desktop

**解决的问题：** 当前 AI 代理主要通过截图 + 像素匹配或 DOM 注入操控 GUI，效率低且易碎。该项目直接读取操作系统的无障碍树（Accessibility Tree），以 JSON 格式返回可操作的 UI 元素引用（ref），让代理无需视觉识别即可精准操作桌面应用。

**技术亮点：** 跨平台（macOS/Windows/Linux）、Rust 实现、60 个命令、Apache-2.0 开源。提供 `libagent_desktop_ffi` 供进程内调用，内置 MCP 支持，可与 Claude Code 等 AI 编码代理直接集成。隐私保护意识强：README 明确警告 snapshot 数据含敏感信息，勿上传。

**采用信号：** 由 Vercel Labs 出品（Vercel 是全球最大 Next.js 托管平台），背书可信度高；项目网站 agent-browser.dev/desktop 已上线；GitHub Topics 覆盖 computer-use、mcp、ai-agents 等高流量标签。

**适用人群：** 构建 RPA 自动化、AI 桌面助手、测试自动化、无障碍工具的开发者。

**风险与关切：** 项目仍处早期（仅 317 次提交），4 个命令被标记为"暂时拒绝运行"；无障碍树内容天然含有大量屏幕隐私数据，生产使用需严格数据隔离策略。

**许可证：** Apache-2.0 ｜ **维护者：** Vercel Labs 组织 ｜ **URL：** https://github.com/vercel-labs/agent-desktop

## 🥇 第一名深度分析：vercel-labs/agent-desktop

### 1. 项目定位

`agent-desktop` 的定位是 **AI 代理的桌面原生操控层**。区别于基于截图的 computer-use（需要视觉模型理解像素）或 DOM 注入（仅限浏览器），它通过操作系统级无障碍 API（macOS Accessibility API、Windows UI Automation、Linux AT-SPI）直接暴露 UI 元素的语义引用（ref），代理可以通过操作 ref 执行精确动作并验证结果，而无需依赖视觉识别。这是一个面向程序化桌面自动化的轻量、精确路径。

### 2. README / 文档

文档设计规范，体现 Vercel 工程文化：包含详细的跨平台安装说明、权限配置指引、60 个命令清单、`libagent_desktop_ffi` FFI 使用说明，以及明确的隐私警告（截图/剪贴板内容勿上传日志）。`docs/faq.md` 和 `CONTRIBUTING.md` 已到位。相对不足：命令说明较为精简，缺乏端到端的实际用例演示；发布版本标注（Homebrew/Scoop 尚未完成）显示项目仍在快速迭代中。

### 3. 增长与社区指标

- 今日新增：+2,243 stars（snapshot/provisional）
- 总 Stars：~8,497，Forks：~594
- 仅 317 次提交（年轻项目），45 个 open issues，69 个 open PRs
- 16 名 Watchers（数量偏低，反映项目传播仍处早期）
- 未检测到 Discord/Slack 等即时社区渠道

单日增量显著，但绝对体量相对有限，反映项目刚进入公众视野。

### 4. 维护者 / 生态分发

由 **Vercel Labs** 出品，是 Vercel 探索前沿工具的孵化品牌，历史产品包括 AI SDK、v0 等均已产业化。这意味着：背后有充足工程资源、与 Next.js/Vercel 生态的整合路径清晰，但也意味着产品方向最终取决于 Vercel 的商业决策。Apache-2.0 许可确保社区可以在商业化前 fork 自用。

### 5. 相对优势

- **精度高**：无障碍 API 返回精确 UI ref，无视觉模型幻觉风险
- **速度快**：无需截图/图像推理，低延迟
- **跨平台**：macOS/Windows/Linux 三端支持
- **Vercel 背书**：显著降低企业用户采用门槛
- **MCP 原生支持**：直接集成 Claude Code 等 AI 代理生态

### 6. 风险与不确定性

- 无障碍 API 行为在操作系统版本更新时可能发生破坏性变化，维护成本不低
- 隐私数据风险：屏幕内容、剪贴板均可被捕获，企业环境部署需严格数据治理
- 4 个命令暂时禁用，说明存在安全或稳定性顾虑
- Vercel Labs 项目有历史弃用案例，长期维护可预期性存在不确定性
- 目前缺乏社区即时沟通渠道，bug 响应速度未知

**消费端 MoE 推理的两条路径**

FreeToken（Python + GPU 加速）和 colibri（纯 C + 磁盘流式）代表了不同的技术取舍：前者追求在有 GPU 的硬件上最大化吞吐，后者追求在 RAM 充足、GPU 受限的硬件上运行前沿模型。两者同日上榜，说明市场对本地大模型推理需求旺盛，且不同硬件配置的用户均有未满足需求。

**对 Builders 的建议：**
