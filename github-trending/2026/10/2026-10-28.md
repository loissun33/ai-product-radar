### 1. elayadesign/ai-design-skills
**解决的问题：** 当前 AI 编程工具（Claude Code、Cursor、Codex 等）在生成界面代码时，缺乏统一、高质感的设计规范，导致产品视觉同质化严重。本仓库提供一套以 Markdown 编写的可插拔设计技能文件。

**亮点与创新：** 安装极为轻量——将 `.md` 文件复制到对应工具的规则目录即完成集成；设计变量（颜色、字体、间距、动效）集中于单一区域，允许开发者 fork 后按品牌定制。目前包含 `landing-page-design` 一个技能，覆盖落地页结构、转化文案策略和完整视觉系统。

**采用信号：** 9.8k stars，694 forks，MIT 许可证，开放 PR 贡献。仓库仅有 8 次提交，高 star/commit 比表明社区对此需求强烈。

**适用人群：** 希望让 AI 工具输出更具专业感落地页的独立开发者与初创团队。

**风险与关注点：** 目前仅一个设计技能可用，单一维护者风险较高，功能扩展速度有待观察。

**链接：** https://github.com/elayadesign/ai-design-skills | MIT | 维护者：elayadesign

### 2. Nutlope/hallmark
**解决的问题：** AI 工具生成的 UI 普遍存在"AI 廉价感"（AI slop）——过于相似、无个性的视觉风格。Hallmark 是一个专为 Claude Code、Cursor 和 Codex 设计的技能，通过选取结构宏观风格、执行 57 条"俗气测试"门控，并在输出前进行自我批评，强制产出有辨识度的设计。

**亮点与创新：** 内置 21 种设计主题，支持 `audit`（审核）、`redesign`（重设计）、`study`（研究）和默认构建四种操作动词。提供在线 Demo（usehallmark.com），一行命令 `npx skills add nutlope/hallmark` 即可安装。由 Together AI 团队出品。

**采用信号：** 25.5k stars，1.3k forks，MIT 许可证，今日新增 2,830 stars（当日最高），16 个 open issues，26 个 PR 表明社区活跃。

**适用人群：** 全栈独立开发者、设计不强的工程师团队，以及任何希望 AI 生成代码具备高质量视觉输出的用户。

**风险与关注点：** 依赖 AI 的"主观判断"来评估设计质量，不同 LLM 的执行效果可能存在差异；现有主题覆盖范围尚未完整记录。

**链接：** https://github.com/Nutlope/hallmark | MIT | 维护者：Nutlope（Together AI）

### 3. nightly-labs/openbot
**解决的问题：** 开发者在同时管理多个 AI 编程代理（Codex、Claude Code、Grok 等）时缺乏统一工作台，各代理之间无法共享任务、文件或进行协作。Openbot 是一款本地优先的桌面应用，为每个 AI agent 提供独立工作空间，支持任务队列、文件共享、浏览器控制和 agent 间消息传递。

**亮点与创新：** 通过 ACP（Agent Communication Protocol）支持 Codex App Server、Claude Code、Grok CLI、Gemini、Cursor CLI 等多种编程助手；内置先进先出消息队列和 agent 间消息路由；跨平台支持 macOS 13+、Windows 10+ 和 Linux。

**采用信号：** 979 stars，155 forks，2,104 commits，专用 Discussions 区，目前处于 Development Preview 阶段。采用 PolyForm Noncommercial 许可（商业使用需获授权）。

**适用人群：** 同时使用多个 AI 编程助手的重度用户、多 agent 工作流研究者。

**风险与关注点：** 代理默认以 `danger-full-access` 和 `approvalPolicy: never` 模式运行，可修改文件和执行命令无需确认，安全风险显著；商业许可限制影响企业采用；开发预览版稳定性存疑。

**链接：** https://github.com/nightly-labs/openbot | PolyForm Noncommercial 1.0.0 | 维护者：Synthetify Labs（nightly-labs）

## 第一名深度分析：elayadesign/ai-design-skills

### 1. 项目定位

`elayadesign/ai-design-skills` 是一个为 AI 编程工具量身定制的设计技能开源集合。其核心理念是：通过在工具的规则目录中放置 Markdown 格式的技能文件，让 Claude Code、Cursor、Codex、Windsurf 等 AI 编程助手"学会"如何产出具有专业水准的 UI/UX 设计代码。目前已发布 `landing-page-design` 技能，覆盖落地页信息架构、转化导向文案策略，以及字体、间距、圆角、动效等完整视觉系统定义。设计变量区独立集中，支持用户 fork 后按品牌定制——这是其区别于其他设计规范工具的关键设计决策。

定位上，本项目填补了"AI 工具设计规范化"的市场空白，面向的是那些需要 AI 工具帮自己输出美观、有个性落地页的独立开发者和初创团队——这一群体往往不具备专职设计师，且正在使用 AI 工具大量生成代码。

### 2. README / 文档

README 结构清晰，提供了针对 Claude Code（`.claude/skills`）、Cursor（`.cursor/rules`）、Codex、Windsurf、Cline 和 Claude.ai 共 6 个工具的独立安装说明，覆盖主流使用场景。设计变量集中区和来源致谢（`Leonxlnx/taste-skill`）显示了良好的工程规范意识。

不足之处：目前只有一个技能可用，文档对技能的实际使用效果缺乏可视化示例或截图对比，新用户难以量化价值。此外没有 CONTRIBUTING.md 或 Issue 模板，贡献路径不够明确。

### 3. 增长与社区指标

以 8 次提交换取 9.8k stars，stars/commit 比极高，表明需求驱动明显而非持续运营积累。今日新增 1,395 stars，在当日榜单中名列第一。694 forks 说明社区有意基于此定制分叉，侧面印证商业化场景真实存在。32 watchers 相对偏低，可能反映仓库在早期"消费大于贡献"的状态。仓库上线时间短且 commit 极少，关注后续活跃度变化是重要指标。

注：上述数据为 snapshot/provisional，不代表最终封榜数字。

### 4. 维护者 / 生态分发

维护者为个人账号 `elayadesign`，GitHub 主页无其他活跃项目背书，背景透明度有限。分发策略依赖用户手动复制文件到各工具目录，与竞品（如 hallmark 提供 `npx` 一键安装）相比便利性偏低。MIT 许可证对商业使用友好，也使二次发行无障碍。

生态上，本项目定位于"多工具通用设计规范"，与 Nutlope/hallmark 和 pbakaus/impeccable 构成同一赛道的竞争与互补关系。

### 5. 相对优势

- **极低的安装成本：** 纯 Markdown 文件，无依赖，无 CLI，任何工具均可使用。
- **高度可定制性：** 设计变量区集中，品牌替换一目了然。
- **广泛的工具兼容性：** 覆盖 6 个主流 AI 编程工具，门槛最低。
- **MIT 许可：** 商业友好，Fork 无障碍。
- **轻量单一焦点：** 相比 ECC（311 个技能）或 superpowers（完整 SDLC 方法论），ai-design-skills 目标明确、上手零认知负担。

### 6. 风险与不确定性

- **单一技能风险：** 当前仅一个 `landing-page-design` 技能，应用场景极为有限，未来扩展速度决定项目生命周期。
- **单一维护者风险：** 无组织支撑，无贡献者，长期维护不确定性高。
